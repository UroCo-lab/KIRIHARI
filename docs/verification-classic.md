# 試作版の検証結果

2026年11月5日。Windows 11（ビルド 26300、実行ホストの表示倍率150%）で KIRIHARI.exe をビルドし、WPF の操作イベント、ダイアログ、描画、ローカルファイル処理を検証した。テストは build.ps1 -Test で再実行できる。

| ケース | 検証内容 |
| --- | --- |
| A · 基本操作 | 架空映像を再生。ドラッグで採用3区間を作成し、端のドラッグ、1フレーム調整、Undo/Redo、拡大、再生モード切替、保存画面を確認。 |
| B · 説明画面 | 5秒のブランクに画像・文章・矢印を3段で重ねた。透明度と、プレビューでの移動・拡縮・回転を確認。 |
| C · 特殊再生 | 2倍速の4秒を2秒で通過。停止中は元動画上の780フレームに留まり、指定時間後に復帰。元動画座標とタイムライン幅は固定。 |
| D · 時間整合性 | 10秒＋5秒＋2秒＋6秒＋3秒＝26秒をモデルとUIで確認。前方のカット、ブランク、速度の変更に伴うテロップの完成時刻、紐付け消失時の警告、停止時間短縮時の警告とUndoを検証。 |
| E · 小画面と大画面 | 1366×768・1920×1080 のウィンドウ内寸を想定し、100%・125%相当でWPFを描画。小画面でも操作ボタン、3段のテロップ、音声段、保存先の入口を確認。詳細を開くと右欄はスクロールする。 |
| 保存・プロキシ | 相対パス付きの .kirihari の保存、置換、読み戻し、自動保存コピーを確認。プロキシの模擬進捗を開始・中止・再開・リセット。書き出しの画質設定を保存。 |
| 実動画 | 架空のMP4で解像度、12 fps、音声の有無をWindowsから取得。映像再生と音声切替を確認。元ファイルのSHA-256は試験前後で一致。 |

A〜E は実行ファイル内の検証コードから、画面のイベントハンドラと同じ経路を呼び出して確認した。解像度と125%は描画条件を再現したもので、Windowsの画面設定を切り替える試験とは区別する。ネイティブのファイル選択ダイアログは組み込み、テストではその直後のファイルパスを直接渡した。複数の実機、低性能PC、初見の利用者によるマウス操作、USB媒体、OSのネットワークとキャッシュ、GitHub Actions上での実行は未検証。
